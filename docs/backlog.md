## Как читать

- `[x]` — задача подтверждена как выполненная.
- `[ ]` — задача ещё не выполнена.
- `P0` — исправление ошибок или блокирующего поведения.
- `P1` — важное улучшение текущего MVP.
- `P2` — крупная функция, которую лучше делать после стабилизации.
- `сложность: low` — маленькая изолированная правка; `medium` — несколько файлов
  и тесты; `high` — архитектурная или продуктовая работа.

Порядок ниже — рекомендуемый, а не исторический. Сначала закрываются ошибки,
затем быстрые улучшения, затем крупные подсистемы.

## 1. P0: исправить правила и жизненный цикл

### B01 — Учитывать дубликаты ингредиентов при оценке

- **Статус:** `[x]`
- **Приоритет:** P0
- **Сложность:** low
- **Проблема:** `assessSimple` и составной путь используют проверку наличия, а
  не мультимножество. Например, лишняя котлета может не попасть в `extra`, и
  заказ получает слишком высокую оценку.
- **Сделать:**
  - сравнивать количество вхождений каждого id в подносе и рецепте;
  - лишние дубликаты добавлять в `extra`, недостающие — в `missing`;
  - при проверке `ordered` сначала убрать лишние дубликаты, затем сравнивать
    порядок остатка;
  - отдельно проверить simple-предметы.
- **Тесты:** дубль котлеты, `котлета + котлета + сыр`, дубль base, дубль Cola и
  идеальный заказ без дублей.
- **Файлы:** `src/lib/core/services/order-validator.ts`,
  `src/lib/core/services/order-validator.test.ts`.

### B02 — Не оставлять выполненный заказ у исполнителя

- **Статус:** `[x]`
- **Приоритет:** P0
- **Сложность:** low–medium
- **Проблема:** после `serve` сессия сохраняет старый `COMPLETED`-заказ. Это
  может приводить к старому ответу `!заказ` и к тому, что новый заказ
  неправильно выглядит на execution-мониторе.
- **Сделать:**
  - добавить отдельное представление активного заказа (`PENDING` отдельно от
    истории);
  - перевести `!заказ`, `nextDish` и projection на активный заказ;
  - добавить ответ «у тебя нет активного заказа»;
  - закрыть `it.todo` про удаление заказа после `serve` в
    `session-manager.test.ts`;
  - добавить сценарий
    `serve → !взять → !заказ → монитор показывает новый заказ`.
- **Файлы:** `session-manager.ts`, `chat-commands.ts`, `replies.ts`,
  `projector.ts` и соответствующие тесты.

### B03 — Не принимать игровые команды без активного заказа

- **Статус:** `[x]`
- **Приоритет:** P0
- **Сложность:** low
- **Сделано:** `putIngredientEffect`, `serveEffect` и `binEffect` проверяют
  `PENDING` до enqueue; добавлены typed `NoOrderError`/`NoActiveOrderError` и
  соответствующие `GameEvent`-ветки `NOT_IN_GAME`/`NO_ACTIVE_ORDER`.
- **Тесты:** покрыты команды после `serve`, после timeout и без сессии.

### B04 — Уведомлять о таймауте и убирать карточку с монитора

- **Статус:** `[x]`
- **Приоритет:** P0
- **Сложность:** medium
- **Сделано:** `SessionManager` публикует typed `order_expired` lifecycle event
  только на одном terminal transition; `ChatBot` отправляет уведомление в первый
  канал из `TWITCH_CHANNELS`, а unsubscribe освобождается вместе с
  `ChatBotHandle`.
- **Проверка:** XP и lifecycle event меняются один раз; overlay event сразу
  меняет snapshot на `EXPIRED`, поэтому execution-карточка исчезает.

### B05 — Согласовать два разных дедлайна заказа

- **Статус:** `[x]`
- **Приоритет:** P0
- **Сложность:** medium
- **Сделано:** `IOrder` хранит `spawnedAt`, `takenAt` и вычисляемый `deadline`;
  входящий слот использует `spawnedAt + SLOT_LIFETIME_MS`, взятый заказ —
  `takenAt + ORDER_TIME_LIMIT_MS`, а projector читает единый `deadline`.
- **Тесты:** clock-тесты taken deadline и отдельные contract-тесты
  incoming/active overlay подтверждают оба дедлайна.

## 2. Быстрые независимые улучшения

### B06 — Заполнять все пустые слоты за один спавн

- **Статус:** `[x]`
- **Приоритет:** P1
- **Сложность:** low
- **Сделано:** `spawnEffect()` заполняет все свободные слоты одной волной; у
  каждого заказа отдельный burn-fiber, а `SPAWN_INTERVAL_MS` остаётся интервалом
  между волнами.
- **Тесты:** проверяются полная волна, cap по `SLOT_COUNT`, независимое сгорание
  и отмена burn только взятом слота.

### B07 — Сделать bootstrap устойчивым к HMR

- **Статус:** `[x]`
- **Приоритет:** P1
- **Сложность:** low
- **Сделано:** `hooks.server.ts` отключает `ChatBotHandle` и runtime через
  `import.meta.hot.dispose`; bootstrap умеет пересоздать runtime после shutdown.
- **Проверка:** `bootstrap.test.ts` проверяет пересоздание runtime; production
  build и signal cleanup проходят.

### B08 — Закрывать SSE-подключение при размонтировании страницы

- **Приоритет:** P1

- **Тест/проверка:** `overlay-store.test.ts` проверяет malformed payload,

### B09 — Разрешать команды автоматически по уникальному префиксу

### B10 — Привести вид мониторов к плану

## 3. P1/P2: контент и подсистемы

### B11 — Генерировать заказы для группы из 1–4 человек

- **Статус:** `[x]`
- **Приоритет:** P1
- **Сложность:** medium
- **Сделано:** `OrderFactory` сначала выбирает локальный размер группы 1–4 с
  весами `30/30/25/15`, затем генерирует основные порции, дополнительные порции
  и повторы; `personCount` не добавляется в `IOrder` и не отображается в UI.
- Время заказа масштабируется по размеру группы и количеству дополнительных
  порций.
- **Проверка:** тесты размеров 1–4, неравномерного состава, повторов и времени;
  полный `test`, `check`, `lint` и `build` проходят.
- **Файлы:** `core/config.ts`, `services/order-factory.ts` и тесты.

### B12 — Подключить настоящий miniplex SIM

### B13 — Перейти с polling SSE на события

## 4. После MVP

Эти идеи не входят в ближайшую очередь, но остаются в проекте:

- [ ] физика столкновений персонажей;
- [ ] очереди у станций;
- [ ] скорость персонажа в зависимости от уровня;
- [ ] pathfinding по проходам кухни;
- [ ] второй поднос или оставление подноса на станции;
- [ ] несколько одновременных заказов у одного игрока и очередь заказов;
- [ ] автоматическое завершение текущего блюда;
- [ ] уборка и мойка станций;
- [ ] жарка котлет и выпечка пиццы;
- [x] production-контракты переведены на Effect; legacy `{ ok: ... }`-адаптеры
      удалены из orchestration-кода.
- [ ] звук и визуальные эффекты по событиям SIM;
- [ ] анимации получения и удаления заказов;
- [ ] менее хрупкие тесты без жёстко заданных XP, вердиктов и реплик;
- [ ] сортировка multi-dish заказа по максимальному совпадению блюд;
- [ ] поиск ингредиентов с учётом нижней/верхней базы.
- [ ] видимость execution-заказов: отдельный overlay-сервис по `order.id`;
      карточка раскрывается через `!заказ` и исчезает после завершения или
      вытеснения. Нужно для режима «собираю по памяти / смотрю по запросу».
- [ ] live-таймеры view: локальный тик обратного отсчёта для входящих заказов.
      Нужно, чтобы цифры реально обновлялись без серверного polling.
